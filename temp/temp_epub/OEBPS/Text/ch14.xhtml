Capítulo 14: Servicios de Red IPv4 e IPv6

Introducción: Los Servicios que Hacen Funcionar la Red

Si los cables y routers son el cuerpo, DHCP y DNS son el oxígeno y el lenguaje. Sin DHCP, tendrías que configurar manualmente cada teléfono y laptop que entra al edificio. Sin DNS, tendrías que memorizar 142.250.184.4 para entrar a Google.

Este capítulo trata sobre los servicios que hacen que la red sea automática y amigable para el humano.

DHCP (Dynamic Host Configuration Protocol)

El protocolo de configuración dinámica de host se encarga de asignar direcciones IP automáticamente.

El Proceso DORA

Cuando conectas tu PC, ocurre una conversación de 4 pasos (¡Memorízalos!):

  1. Discover: El cliente grita "¿Hay algún servidor DHCP aquí?" (Broadcast).
  2. Offer: El servidor responde "Sí, tengo la IP 192.168.1.10 disponible".
  3. Request: El cliente dice "Genial, la quiero".
  4. Acknowledge: El servidor confirma "Es tuya por 24 horas".
💡 Consejo de Examen: DORA = Discover, Offer, Request, Acknowledge. Es una de las preguntas más frecuentes.

Configuración del Servidor DHCP

  • Scope (Ámbito): El rango de direcciones IP que el servidor puede repartir (ej: 192.168.1.100 a .200).
  • Lease Time (Tiempo de concesión): Cuánto tiempo te presta la IP.
  • Reservation (Reserva): Asignar siempre la misma IP a una dirección MAC específica (útil para impresoras de red).
  • Exclusions (Exclusiones): IPs dentro del scope que NO deben repartirse (ej: la IP estática del router).
  • IP Helper / Relay: Si el servidor DHCP está en otra subred, el router debe configurarse como un "relevo" para pasar las peticiones DHCP.

DNS (Domain Name System)

El sistema de nombres de dominio traduce nombres humanos a direcciones IP.

Tipos de Registros DNS (Records)

Tipo Nombre Función
A Address Nombre a IPv4 (ej: google.com → 142.250...)
AAAA Quad A Nombre a IPv6
CNAME Canonical Name Alias. "www.miweb.com" es en realidad "servidor1.miweb.com"
MX Mail Exchange Dice dónde enviar el correo electrónico de ese dominio
TXT Text Notas de texto. Se usa para verificar propiedad y seguridad (SPF/DKIM)
PTR Pointer Lo opuesto a A. IP a Nombre (Reverse Lookup)
NS Name Server Indica quién es el servidor DNS autorizado para esa zona
SRV Service Localiza servicios como Controladores de Dominio (Active Directory) o VoIP. Define puerto y prioridad.
CAA Certification Authority Authorization Seguridad: Especifica qué Autoridades de Certificación (CA) pueden emitir certificados SSL para este dominio.
DKIM/SPF/DMARC Email Security Registros TXT especializados para evitar la suplantación de identidad en correos (Phishing).

Jerarquía DNS

Root (.) → Top Level (.com, .org) → Second Level (google.com) → Subdomain (maps.google.com)

NTP (Network Time Protocol)

La sincronización de tiempo es crítica. Si tu servidor tiene la hora mal:

  • Los logs de seguridad no coincidirán.
  • La autenticación Kerberos fallará.
  • Las copias de seguridad pueden fallar.

NTP (Puerto 123 UDP) mantiene todos los relojes alineados con una fuente de tiempo atómica (Stratum 0).

Implementación de IPv6

El mundo se quedó sin direcciones IPv4, así que IPv6 llegó para salvarnos (con direcciones de 128 bits).

Métodos de Transición

  • Dual Stack: La mejor opción. Tus dispositivos ejecutan IPv4 e IPv6 al mismo tiempo.
  • Tunneling: Empaquetar tráfico IPv6 dentro de paquetes IPv4 para cruzar una red vieja.

Tipos de Direcciones IPv6

  • Global Unicast: Pública (empieza por 2000::/3).
  • Link-Local: Privada, solo funciona en el cable local. Obligatoria. (Empieza por fe80::).

SLAAC (Stateless Address Auto-Configuration)

SLAAC permite que los dispositivos se autoconfiguren sin un servidor DHCP central. El router solo informa sobre la red, y el cliente hace el resto.

⚡ Datos Críticos: El Proceso SLAAC de 5 Pasos

Es fundamental para el examen conocer el orden de estos mensajes:

Paso Acción Descripción Técnica
1 Iniciación El dispositivo genera su dirección Link-Local (fe80::).
2 Router Solicitation (RS) El dispositivo pregunta: "¿Hay algún router aquí?" (Multicast).
3 Router Advertisement (RA) El router responde con el Prefijo de Red y la Puerta de Enlace.
4 Configuración El dispositivo combina el Prefijo + Interface ID (vía MAC/EUI-64).
5 Verificación (DAD) Duplicate Address Detection: Grita "¿Alguien tiene esta IP?" para evitar conflictos.

Comparativa Rápida

  • DHCPv4: Servidor central asigna todo (Stateful). Si el servidor cae, no hay IP.
  • SLAAC (IPv6): Descentralizado (Stateless). El router da el prefijo, la gestión es del cliente.

⚡ Datos Críticos: Prefijos de Direcciones IPv6

Tipo de Dirección Prefijo (Hex) Equivalente IPv4 / Uso
Global Unicast 2000 - 3999 IP Pública (Internet).
Link-Local FE80 APIPA / IP Privada (Solo LAN).
Multicast FF Broadcast (Enviar a grupo).
Loopback ::1 127.0.0.1 (Localhost).
Ruta por defecto :: 0.0.0.0 (Cualquier red).

El Proceso EUI-64

Para generar el Interface ID de 64 bits desde una MAC (48 bits):

  1. Divide la dirección MAC a la mitad.
  2. Inserta FFFE en el medio.
  3. El resultado es el identificador EUI-64.

🛠️ Escenario: ¿Por qué no salgo a Internet con IPv6?

Síntoma: Un usuario imprime en la red local pero no navega. Al revisar ipconfig, su dirección comienza con FE80::.

  • Diagnóstico: FE80 es Link-Local. Solo permite comunicación LAN.
  • Causa: No está recibiendo una dirección Global Unicast (2000-3999) del router.
  • Solución: Verificar que el router esté enviando Router Advertisements (RA) correctamente.

📌 Resumen de Puntos Clave

  • DORA: Discover, Offer, Request, Acknowledge (Proceso DHCP).
  • Registros DNS: A (IPv4), AAAA (IPv6), MX (Correo), CNAME (Alias).
  • IP Helper: Necesario si el servidor DHCP está en otra VLAN.
  • SLAAC: Autoconfiguración de IPv6 sin servidor central.
  • NTP: Mantiene la hora sincronizada (Vital para seguridad/logs).
💡 Consejo del Instructor: Si ves una pregunta sobre "un usuario puede acceder a servidores por IP pero no por nombre", es un problema de DNS. Si la IP del usuario es 169.254.x.x, es un problema de DHCP.
